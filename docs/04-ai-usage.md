# 04 - AI 使用（AI Usage）

> 本文档如实记录 AI 辅助的范围、个人贡献与验证方式。评审者可对照 git 历史与 Trace 交叉验证。

## AI 辅助的范围

本项目在 AI 辅助工具（编码智能体）支持下完成，具体分工如下。

**AI 承担的部分**

- 依据候选人的设计方案生成项目脚手架与全部代码：工具层（含幂等与单次故障注入）、ReAct 循环、Mock/API 双模型入口、CLI、Trace 记录
- 生成验收场景的测试代码与合成数据（素材库/费用表）
- 生成 examples/ 的实际运行输出、Trace 与测试记录
- 起草 docs/ 五篇文档与 README

**候选人承担的部分**

- 题目理解与验收标准确认：把题目 5 个必验收点 + 重复执行 + 加分项"失败步骤续跑"转成可断言的成功标准
- 核心设计决策（见 [02-solution.md](02-solution.md)）：
  - 选定"原生实现 + CLI + Mock/API 双入口"的技术路线与边界声明
  - **费用事实与预算判断分离**：estimate_cost 只返回费用事实，超预算换档、缺口计算、重规划全部留在模型侧，保证"合理重规划"是真实的动态决策而非预设分支
  - 幂等放工具层（topic:tier 键）、失败状态按观察记录等"模型不是安全边界"的结构性约束
  - 失败处理策略：瞬时故障重试一次（续跑），检索不到素材等确定性失败不重试直接如实终止
- 设计评审与修正：修正一次性生成脚本在场景间复用同一数据目录导致的数据污染（normal 场景已保存方案污染后续场景的预期状态）——每个验收场景必须用独立数据目录
- 逐项验证（见下节）
- 本文档及各文档的核对修订

【候选人补充：实际投入用时、未完成部分与个人修改的具体细节】

## 验证方式

AI 生成的产物不默认可信，按以下方式验证：

1. **自动化测试**：`python -m unittest discover -s tests -v`，9 个用例覆盖全部验收点 + 失败续跑加分项 + 步数上限 + CLI 边界，实际结果见 [examples/test-results.txt](../examples/test-results.txt)。
2. **红线核对**：对全部场景断言已保存方案费用合计 ≤ 预算、失败步骤保留 failed 记录、未完成必有原因与缺口（`tests/test_acceptance.py::assert_red_lines`）。
3. **Trace 抽查**：人工核对 `examples/*.trace.json`，确认每步工具参数、观察结果与决策依据一致，无跳步（如未检索就生成脚本、未估算就保存）。
4. **参考实例对拍**：用题目参考实例（预算 10，standard 估算 12 超限 → 改选 8 的方案 → 再估算和保存）作为金标准用例复现，见 `examples/budget-overrun.*`；无可行方案缺口 3 见 `examples/no-feasible.*`。
5. **可复现性**：评审者按 README 命令从零运行，应得到与 examples/ 一致的结果（run_id 与时间戳除外）。

## 边界声明

- 仓库内不包含任何真实密钥；`.env.example` 仅列出变量名。
- Mock 模型是离线确定性策略，**它验证的是 ReAct 流程与工具协议，不证明真实模型效果**——这一边界同样适用于 examples/ 中的全部运行记录。
