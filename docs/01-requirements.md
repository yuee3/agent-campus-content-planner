# 01 - 需求（Requirements）

## 用户与目标

- **用户**：小影校园内容团队的运营同学。
- **目标**：在给定的**预算与截止时间**内完成一场内容活动的方案——检索素材、生成脚本、估算成本，把**不超预算的活动方案**保存下来；预算不够时调整档位重规划，实在没有可行方案时给出未完成原因与缺口。
- **Agent 的定位**：活动方案规划助手，不是投放执行者。

## 输入与材料

| 材料 | 内容 | 来源 |
| --- | --- | --- |
| 用户请求 | 主题 `topic`、预算 `budget`、截止时间 `deadline`、故障注入 `inject` | 任务输入 JSON |
| 素材库 | 主题 × 档位（standard/lite）的素材清单与内容形式 | `data/materials.json` |
| 费用表 | 各档位方案的分项费用（脚本撰写/渠道推广）与工具耗时 | `data/cost_table.json` |
| 方案箱 | 已保存的活动方案 | `data/plans.json` |

可用的业务工具（题目指定四类，均为本地函数实现）：素材检索、脚本生成、成本估算、方案保存。

## 交付结果

对每次请求输出（固定 JSON 结构，见 `examples/*.output.json`）：

- 任务计划与步骤状态（`plan.steps`：每步的工具、档位、`success/failed` 状态）
- 工具结果（Trace 中每步的参数、观察与决策依据）
- 费用合计（`cost`：预算、估算合计、分项、是否在预算内）
- 已保存方案（`saved_plan_id`）**或**未完成原因与缺口（`incomplete_reason`）

**仅保存方案，不接真实投放**——系统中不存在投放/发布工具。

## 范围

**做（In Scope）**

- 单主题、单请求的方案规划流程
- ReAct 动态决策：依据工具观察结果选择检索 / 生成 / 估算 / **超预算换档重规划** / **失败重试续跑** / 如实终止
- 离线确定性 Mock 模型入口 + OpenAI 兼容 API 入口（双路径共用同一循环）
- CLI 运行方式、5 个验收场景（+ 加分项）+ 重复执行、自动化测试与 Trace 记录

**不做（Out of Scope）**

- 真实投放动作、多活动批量规划、跨活动预算分配
- 界面 / 线上部署 / 多 Agent / 生产级 Runtime
- 跨会话长期记忆（任务为一次性请求）

## 成功标准

1. **5 个必须验收点 + 重复执行全部通过**：正常完成、缺预算或截止时间、工具失败、预算超限（换档重规划）、无可行方案返回缺口、重复执行幂等。**加分项**：失败步骤续跑且保留已成功步骤结果。
2. **3 条红线不越界**：
   - 已保存方案的费用合计必须 ≤ 预算且等于估算值——**不得把超预算方案存为可行**；
   - **失败步骤不得记为成功**（步骤状态按实际观察记录，失败保留 `failed`）；
   - 未完成必须给出原因与缺口，不编造、不虚报。
3. **真实 ReAct 循环**：模型（或 Mock 策略）基于工具观察结果调整下一步动作，而非固定条件分支；Trace 中可还原每一步的工具参数、返回摘要与决策依据。
4. **步数上限**：执行步数达到上限（默认 12）时返回明确的 `incomplete` 未完成状态。
5. `python -m unittest discover -s tests -v` 全部通过（实际结果见 `examples/test-results.txt`）。

## 参考实例的对应实现

> 预算 10 时初始方案估算 12 超预算 → 改选估算 8 的方案 → 再估算和保存；没有任何可行方案时返回未完成及缺口；不能把失败步骤记为成功。

- 预算超限换档：见 `examples/budget-overrun.*` —— 预算 10，standard 档估算 12 超限 → 观察到超预算后改选 lite 档 → 再估算（8）→ 保存，费用合计 8 ≤ 10。
- 无可行方案：见 `examples/no-feasible.*` —— 预算 5，连最低档 lite 都估算 8 → 不保存任何方案，返回未完成并写明缺口 3。
- 失败步骤续跑（加分项）：见 `examples/tool-failure.*` —— 注入一次脚本生成失败 → 重试成功；失败步骤保留 `failed` 记录，已成功步骤结果全部保留。
